# 味记・王 产品需求文档（PRD）

> **一句话**：把抖音、小红书、B 站里收藏的美食教程收进来，自动排成今晚能照着做的一道菜，并记住你每次做时的改动。
> 这不是菜谱库、不是社区、不是信息流。它只回答一个问题：**「我收藏的这份教程，今晚能不能做出来？」**

## 1. 用户与场景

**核心用户**：一二线 25-35 岁，工作日晚餐为主，1-2 人份；在手机上刷到教程，在厨房里用手机或平板照着做。

| 场景 | 频率 | 当前做法 | 失败点 |
|---|---|---|---|
| 刷到教程，先收起来 | 每天数次 | 平台收藏夹 | 只进不出、搜索弱 |
| 做饭前找菜 | 每天 1-3 次 | 翻收藏、问人、点外卖 | 找不到、想不起来 |
| 照着视频做 | 每周 3-5 次 | 反复拖进度条、截图、抄食材 | 手忙、熄屏、看不清 |
| 备菜与采购 | 每周 1-3 次 | 备忘录、脑子记 | 漏买、重复买 |
| 复做同一道菜 | 每周 2-4 次 | 凭记忆 | 上次的改动忘了 |

## 2. 产品原则（不可妥协）

1. **收藏不是目的，做出来才是。** 首页不展示收藏瀑布流，展示「今晚吃什么」与「最近做过」。
2. **一条链接进来，能自动的全自动。** 解析、下载、抽封面、排步骤、拆食材，用户只做确认与修正。
3. **任何失败都不丢数据。** 解析失败保留链接与文字；下载失败保留已得内容；永远可以手动补。
4. **厨房里的人因优先。** 大字、大按钮、常亮、少手势、可语音；不做需要精细操作的花活。
5. **数据属于用户。** 零账号、零上传；一条菜谱一个文件夹；可导出 zip + Markdown；换机可恢复。

## 3. 核心闭环

```
刷到 → 分享/粘贴链接 → 解析（抖音/小红书/B站）
     → 下载视频/图片（优先无水印源）+ 解析文字
     → 自动排版：封面、食材、步骤、来源
     → 用户确认/补全（菜名、份量、关键步骤）
     → 开始做（烹饪模式）→ 做完记录（评分、改动、照片）
     → 下次优先显示「我的版本」
```

## 4. 功能范围

### P0（MVP，必须可用）

| 模块 | 能力 | 验收标准 |
|---|---|---|
| 收录 | 系统分享、粘贴链接、手动建卡 | 3 步内生成草稿；失败保留链接 |
| 解析 | 抖音（WebView）、小红书（页面 JSON）、B站（公开 API） | 三平台各 20 条样本成功率 ≥70%；字段缺失不崩 |
| 媒体 | 视频、图片下载；无水印源优先；封面抽帧 | 下载可断点续传；失败可重试；不覆盖已有文件 |
| 排版 | 标题、作者、正文、食材、步骤草稿 | 食材/步骤可编辑；解析置信度低时明确提示 |
| 菜谱库 | 列表、搜索、收藏、标签、排序 | 1000 条内滚动 60fps；搜索 <300ms |
| 详情 | 食材按份量缩放、步骤、原文、来源署名 | 份量 1-8 人联动；「适量」不误算 |
| 烹饪模式 | 大字、常亮、上一步/下一步、计时器、音量键 | 湿手可操作；误触返回有确认 |
| 记录 | 烹饪记录、评分、备注、我的版本 | 做完 10 秒内可记录；下次优先展示 |
| 采购 | 食材加入清单、勾选、分组、清除已购 | 可脱离菜谱独立存在 |
| 备份 | 导出 zip（含媒体）、从 zip 恢复 | 换机后菜谱、图片、视频、记录完整 |
| 设置 | 主题、仅 Wi-Fi 下载、登录态管理、清除 Cookie | 清除后无法再解析需登录的平台 |

### P1（第二次迭代）

- 图片 OCR（从截图提取文字）
- 语音朗读步骤（TTS）
- 多计时器并行 + 后台响铃
- WebDAV 同步
- 分享菜谱为长图/PDF
- 厨房模式的手势免触（音量键已覆盖）

### P2（以后）

- 视频转步骤（ASR + 关键帧）
- 智能推荐「今晚吃什么」
- 多设备局域网同步
- 菜谱版本对比

### 明确不做

- 公开社区、评论、点赞、关注
- 菜谱商城、广告、订阅
- 批量下载、遍历主页、站内搜索抓取
- AI 抹除水印、裁剪水印区域
- iOS / Web 版本（暂不做，领域层保留可移植性）

## 5. 关键规则

### 5.1 收录与解析

- 只处理**用户主动提交的单条链接**；不做后台监控。
- 平台适配器可插拔；平台改版只换适配器。
- 元数据字段全部可空；UI 用「未获取」占位，不显示假数据。
- 每条菜谱强制保留平台、作者、原链接；这是 `NOT NULL` 级的产品约束。
- 登录态仅本地加密保存，绝不进入导出包、日志、崩溃上报。

### 5.2 份量

- 份量是菜谱的一等属性，默认 2 人份。
- 有明确数量的食材按比例缩放；「适量/少许/若干」原样保留，不参与计算。
- 范围（2-3 勺）按区间缩放，保留区间。
- 结果做厨房取整：≥100 取 5 的倍数，10-100 取整，1-10 保留一位小数。

### 5.3 我的版本

- 原版（来源快照）与「我的版本」并存，不覆盖原版。
- 每次烹饪记录可附带一句改动；第三次做同一道菜时，默认展开「我的版本」。

### 5.4 数据与隐私

- 零账号、零上传、零广告、零统计 SDK。
- 数据库与媒体在应用私有目录；导出由用户显式选择位置。
- Auto Backup 只包含 DB、recipe.json 与封面/步骤图，不包含视频与 Cookie。

## 6. 成功指标

| 指标 | 定义 | 目标 |
|---|---|---|
| 北极星：7 日复做率 | 收录后 7 天内至少产生 1 条烹饪记录 | ≥30% |
| 收录完成率 | 分享/粘贴后成功生成菜谱 | ≥85% |
| 解析有效率 | 三平台样本中拿到标题+至少 1 个媒体 | ≥70% |
| 首次可用时长 | 从分享到菜谱可打开 | 中位数 <15s |
| 崩溃率 | 会话崩溃 | <0.5% |
| 冷启动 | 首页可交互 | <1.2s（中端机） |

## 7. 风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| 平台改版/风控 | 解析失效 | 适配器隔离；熔断；保留链接与手填 |
| 无水印源被收紧 | 只能拿带水印版本 | 标注来源；不 AI 抹除；用户可自备素材 |
| 视频体积 | 存储膨胀 | 默认仅 Wi-Fi 下载；显示占用；可逐条删除媒体 |
| 登录态泄露 | 隐私 | 加密存储；不进备份；一键清除 |
| 进程被杀导致下载中断 | 数据不一致 | .part 原子写；断点续传；草稿可重试 |
| 解析结果错漏 | 信任崩塌 | 置信度提示；三类字段高亮可编辑；宁可少切 |
