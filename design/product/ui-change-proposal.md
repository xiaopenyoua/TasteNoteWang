## 2. 首页「今天吃什么」与采购联动

### 2.1 目标

- 「今天吃什么」不再是自动推荐，而是用户从菜谱里手动挑选的当前菜单。
- 加菜谱到「今天吃什么」时，同一事务把这道菜的食材加入采购清单。
- 从「今天吃什么」移除菜谱时，只减去**这道菜贡献的采购数据**；手动添加的采购项保留；任何数量保底为 0，不出现负数。
- 当天菜单按日期留档：首页日历可回看「吃过的菜」；历史只读，不参与今天的采购。

### 2.2 首页

- 区块标题从「今晚吃什么」改为「今天吃什么」；**不再放「从菜谱选择」动作，也不再放虚线添加卡**。
- 菜谱行（纵向列表）：`surface` 底、16dp 圆角、高 92dp、左右 16、行距 8；左侧 72×72dp 缩略图（圆角 12），右侧菜名 17/22 两行 + 平台徽章 + 份量，右端 11/14 绿字「已加入采购」。
- 左滑行：卡片左移 88dp，右侧露出 88dp 红色「删除」按钮；同时只允许一行展开，点其他行或空白处收起。
- 再次左滑（≥24dp）或点「删除」：立即从今天菜单移除，不弹确认；同时减去这道菜的采购贡献，手动项保留、数量保底 0。列表下方 11/14 灰字提示「左滑卡片可移除；移除会减去这道菜的采购食材，手动项保留。」
- 有菜谱但今天菜单为空：`surface` 卡片「还没有安排今天的菜」+ 说明「在菜谱详情或长按菜谱，点『今晚做这道』」+「去菜谱」文字按钮。
- 删除「最近做过」「快速开始」两段，以及自动推荐卡与「收藏 N 天未做」提示；首页只剩「今天吃什么」一段。
- **首页不显示右下角 FAB**；新增菜谱走「菜谱」页的 FAB 或收录入口。
- 页头右上角新增 36dp 圆形日历按钮（`surface` 底、22dp 日历图标），进入「吃过的菜」（见 2.7）；今天菜单为空时照常可用。

### 2.3 菜谱页长按菜单

- 长按菜谱卡打开底部菜单：
  - **今晚做这道**（主）：加入今天吃什么 + 食材加入采购。
  - **收藏 / 取消收藏**。
  - **删除菜谱**（红）。
- 菜单显示菜名与「加入今天吃什么，并把食材加入采购」说明。

### 2.4 详情页入口

- 食材页底部主按钮改为「今晚做这道」，下方 11/14 绿色提示「加入今天吃什么，并把食材加入采购清单」。
- 成功后弹确认「已加入今天吃什么」+ 说明「从今天吃什么移除时会自动减去对应食材」。

### 2.5 采购来源与扣减

- 原始采购行保留来源：`recipeId`（菜谱贡献）或 `null`（手动）。
- 合并行副行显示来源：
  - 「今天吃什么 · 2 道菜谱」
  - 「今天吃什么 · 2 道菜谱 + 手动」
  - 「手动添加」
- 移除今天菜单中的菜谱：
  - 删除该 `recipeId` 的全部原始贡献；
  - 手动行不动；
  - 合并数量重算；若为 0 且没有手动贡献，删除该合并行；若有手动贡献，只显示手动数量；**任何情况不小于 0**。
- 手动删除合并行 = 删除该名称的全部来源（菜谱 + 手动）；之后移除菜谱时无数据可减。
- 勾选合并行 = 勾选全部来源；部分勾选显示半选（横线）。
- 编辑已在今天菜单中的菜谱并保存：同步替换该菜谱的采购贡献（先删旧贡献，再按新食材/份量写入），避免残留旧食材。
- 删除菜谱：同时删除今天菜单行、采购贡献、步骤备注、整菜备注、步骤媒体。

### 2.6 数据模型

- 新增 `MealMenuEntity(date TEXT, recipeId TEXT, addedAt INTEGER)`，主键 `(date, recipeId)`；`date` 是本地日期 `yyyy-MM-dd`。
  - 今天菜单 = `date = 今天` 的行；其余行即「吃过的菜」历史，只读。
  - 不做午夜定时任务：日期变化后自然读到空菜单，旧行留在历史里。
  - 同一天重复加入同一道菜不重复插入。
- 复用 `ShoppingItemEntity`：
  - `recipeId != null` = 菜谱贡献（从详情/长按加入，必同时进今天菜单）；`recipeId == null` = 手动项。
  - 同一菜谱 + 同名 + 同单位只保留一行；重复加入不重复累加。
  - 合并行是读取时聚合，不存数据库。
- 采购只反映**今天**的菜单：应用启动/回到前台时执行一次 `dropStaleContributions()`，删除 `recipeId` 不在今天菜单里的采购贡献；手动项不动。昨天留下的菜不会继续挂在今天的采购清单里。
- 事务：
  - `addRecipeToTodayAndShopping(recipeId, servings)`：插入 `(今天, recipeId)`（若不存在）→ 按份量缩放写入该菜谱贡献。
  - `removeRecipeFromToday(recipeId)`：删除今天行 → 删除该菜谱贡献 → 合并视图重算。
  - `saveRecipe`：若菜谱在今天菜单中，替换其采购贡献。
  - `deleteRecipe`：级联清理今天菜单、全部历史行、采购贡献。

### 2.7 「吃过的菜」（历史）

**入口**

- 首页页头右上角日历按钮（36dp）；不占底部导航，不新增 Tab；返回回到首页。

**页面结构**

- 页头：36dp 返回圆 +「吃过的菜」34/40；副标题「按天回看每天的菜单」。
- 月历卡：`surface` 底、16dp 圆角、左右 16；顶部「‹ 2026年11月 ›」17/22；周标题「一 二 三 四 五 六 日」11/14。
- 日格 40dp、圆角 12：日期 15/20；有记录的日期下方 5dp 橙点；今天 1.5dp 橙色描边；选中填充 `primary`、黑字、点变黑 55%。
- 按周一开始；补齐前后月日期，非本月日期 45% 透明度；点非本月日期直接切到对应月份。
- 默认选中今天；翻月后选中该月最后一个有记录的日期，没有记录则选 1 号。

**当天菜单**

- 月历下 SectionHeader：`11月2日 · 周一` + 右侧 `2 道`。
- 行：52dp 封面（圆角 10）+ 菜名 17/22 两行 + 平台徽章 + 份量；点击进详情。
- 选中日无记录：显示「这天没有记录」15/22 灰，不出现整页空状态。
- 整库从未有过菜单：整页空状态，72dp 圆底日历图标、「还没有吃过的菜」、说明「在「今天吃什么」里选几道菜，之后这里会按天留下记录。」、主按钮「去安排今天」。
- 历史只读：不能补记、改菜或删除；今天的菜单仍在首页维护。

**语义边界**

- 记录的是「当天菜单」，不是烹饪打卡；不写 `cook_logs`、不更新 `lastCookedAt`、不影响「没做过」筛选。
- 只存有菜谱的日期；空日期不落库。删除菜谱会同时从历史里消失。

## 3. 详情页

### 3.1 顶部操作

- 封面左上：返回 40×40dp 圆、`surface` 86%、图标 22dp、距安全区 8dp。
- 封面右上：收藏 / 编辑 / 删除，3×40×40dp 圆、间距 8dp、距右 8dp、与返回同一垂直中心。
  - 收藏未选：`FavoriteBorder` + `onSurfaceVariant`；已收藏：实心 + `error`。
  - 编辑/删除：`onSurfaceVariant`；删除打开现有确认对话框。
- **删除底部 70dp 操作条**；详情内容底部 padding 从 96dp 降为 24dp，只保留系统底部导航。

### 3.2 Tab 与默认页

- 仅 3 段：**步骤 / 食材 / 原文**，段高 32dp、外圆角 9 / 内 7、15/20。
- 默认选中「步骤」；进入详情第一眼就是做菜教程。
- 无 tab 切换动画（沿用已实现的分段控件即时切换）。

### 3.3 步骤页（合并原烹饪模式）

顺序：计时条（有计时时）→ 原视频（有视频时）→ 步骤卡 → 我的备注（整道菜）。

**计时**
- 有时长的步骤在头部显示 `10 分 · 计时` 胶囊（11/14，`surfaceVariant` 底）。
- 点击开始倒计时；运行时胶囊变 `primary` 16% 底 + `primary` 字；可暂停/继续。
- 有任意计时器时，步骤页顶部显示横向计时条：`第 1 步 · 09:58 ×`，支持多个；到点震动一次并显示「时间到」。
- 计时只在前台运行；不做通知/后台服务（与现有实现一致）。

**步骤卡**
- 16dp 圆角、`surface` 底、padding 14、卡间距 6。
- 头部：26dp 橙色序号（黑字 13 Bold）+「第 N 步」15/20 灰 + 时长计时胶囊。
- 正文 17/26。
- 媒体条：每一步可有多张图片/视频，横向 104×78dp 缩略图、圆角 12、间距 8、顺序徽标 1..N；视频中心 28dp 播放圆；点击图片打开图片查看器（该步全部图片翻页），点击视频打开全屏播放器。
- 步骤备注：有备注时显示 `surfaceVariant` 底 + 3dp `primary` 左线 + 「备注 · 11月2日」11/14 + 正文 13/18；无备注时显示虚线「＋ 添加这一步的备注」。
- 无步骤：显示圆角 16 空态卡「还没有拆出步骤。可以切到「原文」看来源全文，或点右上角编辑补充。」

**整道菜的备注**
- 步骤末尾 SectionHeader「我的备注」+「记一笔」。
- 纯文字批注卡：日期 15/20 + 「编辑」13/18 primary + 正文 15/22；左侧 3dp `primary` 竖线，卡圆角 16、padding 14。
- 空态：「还没有备注。做完一次，记一句「哪里不一样」，下次就不用重新想。」
- 「记一笔」Dialog：标题「记一笔」、说明「给整道菜的备注，下次做的时候还能看到。」、多行输入 minLines 2 / maxLines 6、取消 / 保存。
- **备注不是烹饪记录**：不写 `cook_logs`、不更新 `lastCookedAt`、不影响「没做过」筛选，也不再要求星级/份量。

### 3.4 食材空态

- 文案：「还没有食材，点击右上角编辑，从原文里补几行。」
- 与右上角编辑入口一致。

## 4. 新建 / 编辑菜谱

### 4.1 食材：一条一条添加

- 删除多行 textarea 与「按换行拆分」。
- 每条一行：名称（weight 1）+ 数量 68dp + 单位 56dp + 删除 44dp 触控；行高 56dp（M3 OutlinedTextField 最小高），行距 8dp。
- 输入框圆角 14、1dp `outline`；聚焦 1.5dp `primary`；错误 1.5dp `error`。
- 数量用**文本键盘**，允许 `2`、`2-3`、`适量`、`少许`、`若干`；模糊量时单位禁用；不做「适量」开关。
- 「＋ 添加食材」48dp 文字行（左对齐、primary），不是虚线框。
- 空态：「还没有食材」+「点下方「添加食材」，或从原文里复制过来」。
- 校验：名称必填；数量/单位可空；重复名称提示「已有同名食材，仍要添加？」。
- 保存：直接映射 `IngredientEntity`，不再调用 `TextParser` 拆行；未改动的导入行复用原 `rawText/amount/unit/scalable`；`rawText` 统一生成**数量前置**格式（如「2-3勺 生抽」）或同步修改 `IngredientScaler.scaleRange`，避免区间被压平。

### 4.2 步骤：逐步卡片 + 多媒体验证

- 删除步骤 textarea；每一步一张卡：
  - 头部：26dp 序号 +「第 N 步」15/20 + 上移 / 下移 / 删除（40dp 触控，首末禁用）。
  - 正文多行输入 17/26，minLines 2 / maxLines 10，单步上限 300 字；字数 11/14。
  - 媒体网格：多张图片/视频，104×78dp、圆角 12、顺序徽标 1..N、图片/视频类型徽标、视频播放角标；每张有左/右移与移除（40/24dp 触控）；「＋ 图片/视频」可多选。
  - 每一步的媒体顺序即详情展示顺序；支持图片和视频混合。
- 「＋ 添加一步」48dp、`surface` 底 + 1dp `outlineVariant`、圆角 14。
- 「从原文导入」：仅当原文解析出 ≥1 步时显示；打开底部 Sheet 预览步骤，支持「追加 / 替换」。若只有一段无编号文案，不伪装能自动拆；提供「按空行 / 按句号」拆分工具，仍拆不出就提示手动添加。
- 长文本提示：仅 1 步且文本 >180 字或含 http 时，显示「这一步像整段导入文案」+「从原文导入」。

### 4.3 封面 / 原视频 / 媒体

- 封面：16:9（379×213dp）、圆角 14、`surfaceVariant` 底、1dp 虚线 `outline`；空态 24dp 加号 + 「选择封面图片或视频」；有图右上 28dp 移除圆、右下「更换」胶囊。
- 原视频：可选，56dp 行；左侧 44×44dp 播放缩略、标题 15/22、元信息 11/14；「添加视频 / 更换 / 移除」。
- 每步媒体与封面/原视频分离：封面用 `coverPath`，原视频与步骤媒体都进媒体表；不在编辑页做「配方级相册」。
- 选择器：系统 Photo Picker：
  - 封面：`PickVisualMedia` + `ImageAndVideo`（单张）。
  - 原视频：`PickVisualMedia` + `VideoOnly`（单个）。
  - 步骤媒体：`PickMultipleVisualMedia(maxItems = 20)` + `ImageAndVideo`，可一次多选、混合。
  - 不申请存储权限；保存时才复制到应用目录；不在后台持有 `content://` 授权。

### 4.4 保存与媒体生命周期

- 单一 `EditViewModel` 持有 `ingredientDrafts`、`stepDrafts`、`mediaDrafts`、`isSaving`；顶部和底部两个「保存」共用同一个守卫，保存中禁用并显示「保存中…」。
- `saveRecipe` 仍是「先删后插」，但媒体差集**只包含用户显式移除的项**：
  - 以 `existing.media` 为基线；未出现在编辑 UI 的媒体（如分享导入的 PHOTO、未被步骤引用的 STEP）原样保留。
  - 新文件用唯一文件名（含 ULID）；DB 事务成功后再删除旧文件；禁止在提交前覆盖仍被引用的文件。
- 删除菜谱时级联删除步骤备注、菜品备注、步骤媒体；同步更新删除确认文案。

## 5. 媒体查看器

### 5.1 视频全屏

- 详情视频卡右下角 32×32dp 全屏按钮（黑 40% 底、16dp 图标、触控 48dp）。
- 打开全屏 Dialog：纯黑、隐藏系统栏、保持同一个 ExoPlayer 实例与播放进度；退出恢复内联播放器，不重建、不 release。
- 控制条：播放/暂停 44dp、时间 13/18、进度 4dp、全屏退出；顶部 96dp / 底部 120dp 黑色渐变；缓冲 40dp、错误重试。

## 6. 平台登录与 Cookie

### 6.1 现有问题（用户实测 + 本机观察）

- 抖音：内置浏览器登录成功（用户实测）。
- 小红书：页面没有登录按钮，只引导打开 App，无法在当前内置浏览器获取 Cookie。
- B站：登录页样式错乱，用户协议无法勾选，无法登录。
- 根因方向：三平台共用一个移动 UA / 一个入口 / 一个 WebView 配置；各平台网页版对 UA、viewport、缩放的要求不同。

### 6.2 技术调研（2026-11-02，公开页面，不含账号）

用 curl 对公开登录页做 UA 对照（不登录、不输入账号、不绕过验证码）：

| 页面 | 移动 UA | 桌面 UA | 结论 |
|---|---|---|---|
| `https://www.xiaohongshu.com/login` | 200，9,065 字节，标题「你访问的页面不见了」 | 200，36,788 字节，标题「小红书 - 你的生活兴趣社区」，含「登录」 | 桌面 UA 才出 PC 登录页；移动 UA 是失效页。但 WebView 登录仍可能被风控/461 拦截 → **标记为受限，不承诺成功** |
| `https://www.xiaohongshu.com/explore` | 200，25,637 字节，落到首页 | 302/跳转到 `/login?redirectPath=…` | 桌面 UA 会引导登录 |
| `https://passport.bilibili.com/login` | 200，948 字节，SPA 壳，自动跳到 `/h5-app/passport/login` | 200，948 字节，停在 PC 900px 登录卡 | **B站登录应使用移动 UA + H5 页**；桌面页在 390px 下会撑到 1101px，表单被挤出首屏 |
| `https://passport.bilibili.com/h5-app/passport/login` | 200，2,138 字节，390px 下正好贴合 | 200，2,138 字节 | H5 只有手机号/密码登录；无扫码、无第三方登录 |
| `https://www.douyin.com/` | 200，72,914 字节 | 200，72,914 字节 | 移动 UA 主入口可用；与用户实测一致 |

已观察到的页面约束：

- **小红书**：默认 WebView UA（含 `wv`）访问 `/login` 会得到 404 或跳到 `oia.xiaohongshu.com/oia` 的「下载 App / 在 App 内打开」页；桌面 UA 才能拿到 PC 登录页。PC 登录页存在手机号验证码与二维码两条路径，但 WebView 内仍可能被 461/滑块/设备异常/同账号多端互踢拦截。`web_session` 通常是 HttpOnly，页面 `document.cookie` 读不到，必须用 `CookieManager.getCookie` + `flush()` 轮询。**结论：小红书不作为「网页登录一定能成功」的能力设计，默认展示受限说明 + 实验性桌面登录入口，不画手机号/扫码表单承诺。**
- **B站**：`passport.bilibili.com/login` 是纯 JS SPA（HTML 只有空 `#passport-app` + bundle）；移动 UA / WebView UA 会自动跳到 `/h5-app/passport/login`，H5 在 390px 下正好贴合，只有手机号/密码登录（无扫码、无微信/微博/QQ）。桌面 UA 会停在 900px 宽的 PC 登录卡，在 390px 视口下布局被撑到 1101px，表单被挤出首屏——**不要给 B站登录 WebView 用桌面 UA**。
- **B站协议不是复选框**：PC/H5 都没有 `input[type=checkbox]`，只有「我已阅读并同意 用户协议、隐私政策」的被动声明，两个链接是 `target=_blank`、点击区约 54×17px。WebView 默认 `setSupportMultipleWindows(false)`，`target=_blank` 会被当作当前页导航而替换登录页，看起来像「点不动/无法勾选」。修复方向是处理新窗口/用 Custom Tabs 打开协议链接，不是画一个不存在的复选框。
- **Cookie 判定**：B站未登录访问域名就会下发 `buvid3`/`b_nut`，所以「Cookie 非空」绝对不能当作登录成功；必须在 `flush()` 后轮询 `SESSDATA`（辅以 `bili_jct`/`DedeUserID`）。现有「清除」调用 `removeAllCookies` 会清掉三个平台的 Cookie，应改成按平台/域定向清除。
- `CookieManager.getCookie()` 对 HttpOnly / SameSite Cookie 的返回行为需在目标 ROM 上真机验证；设计只认认证键，不假设所有 Cookie 都可见。

### 6.3 扫码 / 跳转 App 授权可行性

用户提议「扫码登录」或「跳转到平台 App 授权」。逐条核过公开接口与平台规则：

| 方式 | 抖音 | 小红书 | B站 | 结论 |
|---|---|---|---|---|
| 网页二维码登录 | 未找到可公开调用的 QR 接口；网页登录当前可用 | PC bundle 有 `qrcode/create` / `qrcode/status`，但属于 overseas login，无签名的 POST 实测 500；需要 `x-s`/`x-t` 签名与风控 | `qrcode/generate` 公开可用（返回 `qrcode_key`），`qrcode/poll` 未扫码返回 86101；扫码成功后的 Set-Cookie 需真机扫码验证 | **B站可做原生扫码（待真机验证）；XHS 不可依赖；抖音不设计** |
| 跳转 App 授权（OAuth） | 需要开放平台 client_key、应用审核与回调域名；个人侧载应用无法取得 | 无面向普通开发者的消费端 OAuth；开放平台以广告为主 | 需要开放平台应用与审核 | **不可作为个人侧载应用的登录捷径** |
| OAuth token 能否替代 Cookie | 不能；导入层需要 Web Cookie | 不能 | 不能 | **即使拿到 OAuth，也不能直接用于三平台链接解析** |

**设计结论**

1. **B站：扫码优先**。用 `qrcode/generate` 拿二维码内容，在应用内 native 绘制二维码；每 2s 调 `qrcode/poll`，状态：等待扫码 / 已扫码请在手机确认 / 成功 / 已过期。成功后 `CookieManager.flush()` 并轮询 `SESSDATA`；拿不到则回退移动 H5 手机号登录。
   - 二维码 220×220dp（白底、圆角 12、四周 12dp 静区），下方「等待扫码」15/22、说明 11/14、「刷新二维码」13/18 primary；顶部「扫码登录 / 手机号登录」分段。
   - 过期 180s（以接口返回为准）；刷新换 `qrcode_key`；同一二维码只轮询一个页面。
   - **真机扫码验证前，UI 标注「实验性」**；验证通过后去掉标注。
2. **小红书：不做扫码承诺**。默认展示「网页登录受限」说明 + 「只保留链接」主按钮 + 「尝试桌面版登录（实验性）」次按钮；不画手机号/扫码表单。桌面版 `/login` 可能出页面，但 461/滑块/互踢风险由用户承担且不保证成功。
3. **抖音：保留现有内置浏览器登录**（用户实测可用），不额外做 QR；若后续验证到公开 QR 接口再评估。
4. **跳转 App** 只提供「在 App 内打开」用于查看/分享，不作为登录；明确提示不会把 Cookie 带回应用。

### 6.4 登录工作台设计

**设置页「平台账号」**

- 新增分组「平台账号」，三行：
  - 抖音：状态点 + 「已登录」/「未登录」/「建议重新登录」；右侧箭头。
  - 小红书、B 站同结构。
  - 「清除全部登录信息」红字。
- 状态：`NONE` 未登录 / `UNVERIFIED` 已保存未验证 / `VERIFIED` 已登录已验证 / `STALE` 已过期；超过 30 天文案提示「建议重新登录」，不改变枚举。

**登录页（内置浏览器工作台）**

- 路由隐藏底部导航/Rail/FAB；顶栏 56dp：关闭 48、标题 17/22、刷新 48、缩放 52、更多 48；底部检测栏 96dp。
- WebView 全宽、白底，不使用强制深色；错误页/加载失败 64dp 圆底 + 标题/正文/重试。
- 底部：状态行（绿点「已检测到登录信息」/ 橙点「未检测到」）+「清除」+「保存并返回」；只有检测到**认证 Cookie** 才启用保存。
- 更多面板：入口切换、页面版本（移动/桌面）、缩放 −/＋、清除本平台登录、平台提示。
- 登录检测：`onPageFinished` 后每 1s 读取 Cookie，连续 2 次命中认证键才显示「已检测到」；12s 未命中提示；30s 错误态；离开停止轮询。
- 拦截 `intent://`、`snssdk1128://`、`xhsdiscover://`、`bilibili://` 等 App scheme；拦截时提示「页面想打开 App，已拦截，请使用页面内登录入口」，不离开 WebView。
- 不自动勾选用户协议、不自动填账号密码、不调用原生登录接口、不做签名破解。

**平台配置矩阵（推荐）**

| 平台 | UA | 主入口 | 缩放 | 认证 Cookie 键 | 备用 |
|---|---|---|---|---|---|
| 抖音 | 移动 UA | `https://www.douyin.com/` | 100% | `sessionid` / `sessionid_ss` / `sid_tt` / `sid_guard` | 个人页 |
| 小红书 | **桌面 UA（实验性）** | `https://www.xiaohongshu.com/login` | 100%（应用侧缩放） | `web_session` | `explore`；失败则「只保留链接」 |
| B站 | 扫码（native）/ 移动 UA（H5） | `qrcode/generate` + `qrcode/poll`；回退 `/h5-app/passport/login` | 100% | `SESSDATA` | H5 手机号/密码 |

**降级路径**

1. 刷新页面。
2. 缩放 +/−（默认 100%；小红书/ B站页面 `user-scalable=no` 时用应用侧缩放）。
3. 「换个入口」（主入口/备用入口）。
4. 仍失败：提示「用系统浏览器打开」——**明确说明系统浏览器登录不会把 Cookie 带回应用**，只用于查看/确认账号状态；不提供手工粘贴 Cookie 的入口。
5. 小红书默认就展示「网页登录受限」：主按钮是「只保留链接」，次按钮是「尝试桌面版登录（实验性）」；若桌面 UA 仍被风控/跳 App，不伪装成功。

**安全**

- 只保存 Cookie，不保存账号密码；加密存储；不进备份；清除按钮立即删除；日志不输出 Cookie 值。
- 加密不可用时显式报错，不静默明文回退。

## 7. 采购清单合并

### 7.1 目标

- 同一食材跨菜谱合并；同单位直接相加；可换算时给出更易买的单位（如 10 瓣蒜 ≈ 1 头蒜）。
- 不静默改变用户数据；合并是读取时聚合，原始条目保留。

### 7.2 UI

- 页头副标题：「还需买 5 项 · 已买 1 项 · 已合并 3 条」。
- 页头下：选中态胶囊「合并相同食材」+ 右侧「合并规则」。
- 合并行：
  - 名称 17/26；数量右对齐 17/26；如发生换算显示「1 头（约 10 瓣）」。
  - 副行 11/14：「3 道菜谱 · 已合并 3 条」。
  - 点合并行打开「编辑『大蒜』」Sheet，按来源逐条列出并可改（见 7.4）。
  - 勾选合并行 = 勾选全部来源；若部分已购，显示半选（横线）状态。
  - 删除合并行 = 删除该名称的全部来源（沿用当前无二次确认的行为，后续可加确认）。
- 单来源行：点名称或行尾箭头打开「编辑采购项」Sheet，预填名称 / 数量 / 单位（见 7.4）。
- 「合并规则」Dialog：列出近似换算，并说明「关闭合并可看原始条目」。
- 关闭「合并相同食材」后显示原始逐条行，便于核对/单条编辑与删除。

### 7.3 合并规则（保守，近似值标「约」）

- 名称归一：蒜/大蒜/蒜瓣 → 大蒜；葱/小葱 → 小葱；鸡蛋/蛋 → 鸡蛋；生抽/酱油（仅明确写作生抽）→ 生抽。别名表可扩展，但必须先测试。
- **同单位直接相加**：克+克、勺+勺、个+个、毫升+毫升。
- **仅做少量明确换算**：
  - 大蒜：`10 瓣 ≈ 1 头`。总瓣数 C：C<10 → 「C 瓣」；C≥10 且整除 → 「H 头」；有余数 → 「H 头 + R 瓣」。
  - 勺/汤匙视为同一单位；茶匙单独，不与克互转（密度未知）。
  - 不把克与个、克与勺互转；单位不兼容时保留多行，不做猜测。
- 合并只按「归一名称 + 兼容单位」分组；不同单位显示为同组下的多行，并标「单位不同，未合并」。
- 计算是纯函数 `mergeShoppingItems(...)`，输入原始条目，输出展示行 + 来源；不改数据库。

### 7.4 手动添加与逐项编辑

**添加**

- 页头 36dp 加号打开底部 Sheet「添加采购项」，不再用单个输入框。
- 一行三个字段，沿用编辑菜谱食材的行：食材名称（weight 1）、数量 68dp、单位 56dp；圆角 12、1dp `outline`、聚焦 1.5dp `primary`。
- 数量用文本键盘，允许 `2`、`2-3`、`适量`、`少许`；模糊量时单位不生效；单位可空。
- 说明：「食材与规格分开填；只加入采购清单，不改任何菜谱。」
- 取消 / 添加；名称为空时「添加」禁用；同名 + 同单位已存在时提示「已有同名食材，仍要添加？」，确认后合并为一行。
- 新行 `recipeId = null`、`category = null`（显示在「其他」）；不猜分类。

**编辑**

- 清单里每一项都能改：点名称或右侧箭头打开「编辑采购项」Sheet。
- 同一套三字段预填当前值；保存只改这条采购项，**不改菜谱里的食材**；说明「只改这次采购，不会改菜谱里的食材。」
- 已购项可编辑；编辑后勾选状态保留。
- 合并行（≥2 来源）不直接改合并后的数量：打开「编辑『大蒜』」Sheet，按来源逐条列出（菜谱名 / 手动添加 + 数量 + 编辑），逐条改；底部显示「合并显示 1 头（约 10 瓣）」。
- 删除：行尾垃圾桶仍是单项删除；合并行删除全部来源（沿用现有行为）。
- 空态说明改为「点右上角 + 手动添加，或在菜谱详情、长按菜谱卡加入。」

## 10. 验收标准

- 详情进入即步骤页；无「开始做」；步骤可计时、可看多图/视频；顶部三按钮可用。
- 每一步可添加多张图片与多个视频，混合排序；详情按同序展示；图片可放大、视频可全屏。
- 编辑页食材逐条增删；步骤逐条编辑；保存后详情与编辑一致；保存失败不丢草稿、不覆盖旧媒体。
- 备注可加到具体步骤和整道菜；备注不改变「没做过」筛选与「吃过的菜」历史。
- 抖音/小红书/B站登录页各有独立 UA/入口/缩放；XHS 桌面 UA 显示登录页；B站协议区可点击；保存只在检测到认证 Cookie 后启用。
- 采购清单同名同单位合并；10 瓣蒜显示 1 头；可关闭合并查看原始条目。
- 首页只剩「今天吃什么」；右上角日历进入「吃过的菜」，能按月翻、点日期看当天菜单；历史只读。
- 采购「+」打开三字段 Sheet；清单每一项都能打开编辑；合并行按来源编辑；编辑不回写菜谱。
- 今天吃什么用左侧缩略图行卡；左滑露出删除，二次左滑或点删除即移除，采购同步扣减。
- 今天菜单的加入入口是详情「今晚做这道」与长按菜谱；首页不再有「从菜谱选择」，也没有右下角 FAB；菜谱页 FAB 为 48dp、20dp 图标。
- 加菜谱同时加采购；移除菜谱只减该菜谱贡献、手动项保留、数量不为负。
- 跨天后昨天的菜单进入历史，采购只保留今天菜单的贡献；手动项不受影响。
- 长按菜谱卡可「今晚做这道」；详情「今晚做这道」与长按一致，都会同时加入今天菜单与采购。
- `bash android/tools/verify-layout.sh` 通过；设计稿与本文链接有效。
