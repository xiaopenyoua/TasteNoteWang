# 文档写作规范

## 1. 写作原则

- **先结论，后论证。** 每份文档开头 3-5 行说清"这份文档回答什么问题、结论是什么"。
- **能表格就不写段落**，能列表就不写长句。信息密度优先。
- **区分事实与判断。** 外部数据注明来源与日期；推断标注"（推断）"；未核实标注"（未验证）"。
- **不写正确的废话。** "提升用户体验""方便快捷"这类句子删掉。
- **一份文档只服务一个读者问题。** PRD 回答"做什么"，架构回答"怎么做"，ADR 回答"为什么这么选"。

## 2. 结构模板

```markdown
---
doc: <相对仓库根的路径>/<slug>   # 例：android/docs/architecture
title: <标题>
status: draft
date: YYYY-MM-DD
owner: wang
related: []
---

# <标题>

> 一句话结论。

## 1. 背景与目标
## 2. 结论 / 决策
## 3. 细节
## 4. 风险与未决问题
## 5. 参考
```

小节编号从 1 开始，最多三级标题。超过三级说明该拆文档了。

## 3. 术语表（全仓库统一）

新术语第一次出现时加粗并在文末"术语"小节定义；同一概念全仓库只用一种叫法。

| 概念 | 统一叫法 | 不要叫 |
|---|---|---|
| 用户收藏的一条教程 | **菜谱**（Recipe） | 食谱、方子、笔记 |
| 菜谱中的一步 | **步骤**（Step） | 环节 |
| 若干步骤组成的阶段 | **阶段**（Stage）：备料/烹饪/收尾 | 分组 |
| 原料与用量 | **食材**（Ingredient） | 材料、配料 |
| 一次实际烹饪 | **烹饪记录**（Cook Log） | 打卡、实践 |
| 从外部平台导入 | **收录**（Capture） | 抓取、爬取 |
| 图片/视频等文件 | **媒体**（Media） | 附件、资源 |

## 4. 表格与图示

- 功能矩阵用 ✅ / ⚠️ / ❌，并在表下注明含义。
- 流程用 Mermaid；状态用 Mermaid stateDiagram。
- 不要贴大段代码到产品文档，代码进 `android/docs` 或仓库代码。

## 5. 检查清单（提交文档前）

- [ ] frontmatter 完整且 `doc` 与路径一致
- [ ] 开头有一句话结论
- [ ] 没有未标注来源的数字
- [ ] 没有 `TODO` 遗留在正文（未决项写进"未决问题"小节）
- [ ] 图片在 `design/exports/` 或 `design/wireframes/`，且相对路径可打开
- [ ] 相关文档链接可点
