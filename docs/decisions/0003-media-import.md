# 0003. 收录策略修订：链接解析、媒体下载与无水印源优先

## 背景

ADR 0001 选择了"链接只建卡、媒体由用户从平台官方保存后导入"，理由是合规风险最低。产品所有者随后明确修改该决定：需要解析抖音、小红书、B站的分享链接，尽可能下载视频与图片、解析文字，并优先获取无水印源。分发方式仍为**仅侧载、个人自用**（ADR 0002）。

本决策记录这一变更，并把风险与边界写清楚，避免后续开发时反复摇摆。

## 选项

| 选项 | 能力 | 风险 | 维护 | 结论 |
|---|---|---|---|---|
| 维持 0001 | 只有链接 + 手填 | 最低 | 零 | 被否决 |
| 端侧解析 + 下载（本决策） | 视频/图片/文字，尽量无水印 | 中高：平台协议、账号风控、链接失效 | 中高：平台改版需修适配器 | **采用** |
| 第三方解析 API / 服务端 | 同上，更省事 | 内容与密钥经过第三方；不可控 | 低 | 否决 |

## 决定

1. **端侧完成**：所有解析与下载在手机/平板上进行，不经过自建或第三方服务器。
2. **只处理用户主动分享/粘贴的单条链接**：不做批量、不做站内搜索抓取、不做定时监控。
3. **平台适配器可插拔**：抖音、小红书、B站各一个 `PlatformExtractor`；平台改版时只换适配器，不动主流程。
4. **优先取无水印源**：
   - 抖音：优先 `play_addr` 一类的原始播放流，避免 `download_addr` 的带水印下载流；
   - 小红书：优先原图/原视频字段，避免带水印的展示变体；
   - B站：平台通常无水印；UP 主自加的水印不处理。
   - **不做 AI 抹除、不做裁剪遮挡**。拿不到无水印源时，下载带水印版本并在界面标注。
5. **文字尽量解析**：标题、作者、正文/简介、话题、字幕（可得时）；解析结果进入"待确认"状态，用户可编辑。
6. **登录态仅本地保存**：需要登录的平台通过应用内 WebView 由用户自己登录；Cookie 加密存储，绝不上传、绝不进入导出包、绝不写日志。
7. **署名不可去除**：每条菜谱永久保留平台、作者、原链接；这是产品的硬性字段，不允许为空。
8. **失败即降级**：解析失败→手动建卡；下载失败→保留链接与已抓到的文字；合并失败→保留分离文件；风控→熔断并提示用户自行保存后导入。任何失败都不丢已录入内容。

## 红线（开发时逐条对照）

- 不批量下载、不遍历用户主页、不做站内搜索抓取
- 不破解签名、不伪造设备指纹、不绕过付费/会员内容
- 不做 AI 水印抹除、不裁剪水印区域
- 不做公开分享、不做内容再分发、不收费、不提供给他人
- 不把 Cookie/登录态写入日志、备份或任何导出物
- 不自动播放第三方视频作为"预览"（避免额外请求与版权问题）

## 后果

- 正面：一条链接即可得到视频/图片/文字与排好版的菜谱卡；离线可看；不再依赖用户手动保存。
- 负面：
  - 平台协议与著作权风险由使用者承担；平台账号存在被风控的可能；
  - 适配器会随平台改版失效，需要持续维护；
  - 存储体积显著上升（视频从"可选"变成常见资产）；
  - 小红书的匿名访问与短链有效期问题会让成功率不稳定。
- 缓解：单并发、限速、失败退避、熔断；每次只处理用户显式提交的一条；保留"仅下载封面/不下媒体"的选项。

## 触发重审的条件

- 平台提供官方开放能力；
- 应用从自用转为分发给他人或收费；
- 连续出现账号封禁或平台投诉；
- 维护成本超过每月固定投入的阈值（由实际数据决定）。
