# 0001. 收录策略：链接建卡 + 用户导入官方保存的媒体

> **本决策已于 2026-10-30 被 [ADR 0003](0003-media-import.md) 取代。** 下列内容保留为历史记录，不再代表当前产品方向。

## 背景

产品要解决的核心链路是：在抖音/小红书/B站刷到美食教程 → 收进味记・王 → 照着做。
调研确认了三条可选路线：

- **A. 链接下载**：应用解析链接并下载视频/图片/文字。
- **B. 纯手动**：用户自己上传图片、视频、编辑文字。
- **C. 全平台解析 + 去水印**：尽量抓取并去除水印。

约束：应用最终只给自己用（侧载），不进入应用商店；但不改变平台协议与著作权的基本边界。

## 选项与代价

| 选项 | 用户操作 | 合规 | 稳定性 | 维护 |
|---|---|---|---|---|
| A 链接下载 | 最少 | 违反平台协议；下载即复制 | 依赖平台解析链路 | 高 |
| B 纯手动 | 最多 | 无 | 100% | 零 |
| C 解析 + 去水印 | 最少 | 去除水印已有生效判例；商业性使用风险更高 | 最低 | 极高 |

## 决定

采用 **A 与 B 的混合方案**，不采用 C：

1. **链接只用来建卡**：从用户主动分享/粘贴的文案中提取平台、作者、标题线索、原链接与平台内容 ID，生成一张排好版的菜谱卡。
2. **媒体由用户从官方渠道保存后导入**：用户在抖音/小红书内使用官方「保存到相册」，再通过系统分享或相册多选导入应用。
3. **不做任何视频/图片下载，不做去水印**，不内置平台接口调用。
4. **应用负责排版自动化**：图片排序、抽帧封面、OCR、正文切成食材/步骤草稿、来源署名条。
5. **全程可降级**：链接提取失败时，用户仍可创建空白菜谱并手填，流程不中断。

明确不做：

- 视频/图片下载、去水印、批量抓取
- 后台监听剪贴板（Android 10+ 系统限制，且不必要）
- 自动打开抖音/小红书 App 抓取
- 公开分享社区、任何形式的内容再分发

## 后果

- 正面：流程永远可用；平台改版只影响"标题猜得准不准"；法律与维护风险降到最低；符合"个人笔记"定位。
- 负面：用户每道菜需要多花 10-30 秒在平台内保存媒体；B 站缓存加密，B 站内容只能靠链接 + 文字 + 用户自备素材。
- 后续观察：如果平台提供官方开放能力（如官方分享接口、创作者授权下载），可在不改数据模型的前提下新增来源适配器。

## 触发重审的条件

- 平台推出官方的第三方收藏/导入 API；
- 用户明确要求并接受"仅自己使用"的法律风险（仍不包含去水印）；
- 产品从"个人工具"转为对外分发。
